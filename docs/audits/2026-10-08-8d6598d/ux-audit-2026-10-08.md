## 4. Findings by hunt category

### Hunt 2: Message quality

#### U1 (High) -- `select_runner.py` fallback is silent and conflates misconfiguration with unavailability -- CONFIRMED

- Surface: `github-runner/scripts/select_runner.py:57-93` (every `return fallback`), `:96-106` (output and the `Invalid selector output path` exit); `github-runner/assets/ci.yml:31-43` (`select` job).
- Scenario: the operator has registered the runner, set six variables and one secret per `ci.md:11-22`, and pushes to `main`. The `checks` job runs on `ubuntu-24.04` and `Record execution machine` prints a GitHub-hosted machine. The `select` job log contains exactly `runner="ubuntu-24.04"`. There are fifteen distinct reasons this happens (`TRUSTED_EVENT` false because `ENABLE_SELF_HOSTED` was typed `True`, `TRUSTED_RUNNER_REF` set to `main` instead of `refs/heads/main`, `RUNNER_LABELS` typed as `Linux,X64` instead of a JSON array, `PREFERRED_RUNNER_LABEL` set to a default label, secret missing, runner offline, runner busy, name not unique, label case drift, API error, GHES URL, pagination mismatch...) and the surface distinguishes none of them. Reproduced locally: runs 4, 5 and 6 in section 2 (untrusted ref; CSV labels on a trusted event; default-label routing with an empty token) all print only `runner="ubuntu-24.04"` and exit 0. The operator trying to debug locally hits `Invalid selector output path` (run 3) because the helper insists on `GITHUB_OUTPUT` and the message does not name it.
- What goes wrong / why vulnerable / impact: the design rationale (`select_runner.py:91`, "exception strings can contain credentials") justifies suppressing exception text, not suppressing a non-secret reason code. The primary journey (preferred-runner CI) completes only after the operator reads the source to enumerate the conditions, which is the High bar. Variable-format mistakes are persistent, so every push silently burns hosted minutes while the operator believes the runner is in use.
- Recommended direction: emit a fixed-vocabulary, credential-free reason to stderr (and `GITHUB_STEP_SUMMARY` when present), e.g. `reason=untrusted-event`, `reason=RUNNER_LABELS-not-json-array`, `reason=routing-label-is-default`, `reason=token-missing`, `reason=runner-busy`, `reason=api-error`; fail hard (like `HOSTED_RUNNER`) on static configuration errors that can never succeed (`RUNNER_LABELS` unparsable, routing label in the default set, `GITHUB_REPOSITORY` malformed); make `GITHUB_OUTPUT` optional for a local dry run or name it in the error.
- Acceptance check: `env -i HOSTED_RUNNER=ubuntu-24.04 GITHUB_OUTPUT=/dev/null GITHUB_REPOSITORY=acme/widget PREFERRED_RUNNER_NAME=build-box PREFERRED_RUNNER_LABEL=widget-ci RUNNER_LABELS='Linux,X64' RUNNER_READ_TOKEN=x TRUSTED_EVENT=true python3 github-runner/scripts/select_runner.py` -- fails now: output is exactly `runner="ubuntu-24.04"`, exit 0, nothing on stderr; passes when a line naming the `RUNNER_LABELS` format problem appears (or the helper exits non-zero for that static misconfiguration), with no token material in any output. (No network is reached: the JSON parse fails before the first fetch.)

#### U2 (High) -- `HOSTED_RUNNER` rejection names a rule nobody can look up -- CONFIRMED

- Surface: `github-runner/scripts/select_runner.py:12-16` (allowlist), `:50-52` (message); `github-runner/references/ci.md:16-17` ("accepted by the helper"), `:27` (links to GitHub's full table, says "conservative subset" without listing it); `github-runner/README.md:43`.
- Scenario: the operator follows `ci.md:27` to GitHub's standard-runner table, picks `ubuntu-22.04-arm` (present in that table) because the project is ARM, sets the variable, pushes. The `select` job fails with `HOSTED_RUNNER is required and must be an approved standard GitHub-hosted label` (run 2). The value is set and is a standard GitHub-hosted label, so the message is false from the operator's point of view; the only way to learn the 14 accepted strings is to open the helper source. Same message for case drift (`Ubuntu-24.04`, run 7).
- Impact: the primary journey is stopped at the first CI run and resolves only by reading source (High). Because the same message covers "unset", "not in subset" and "case mismatch", the operator cannot tell whether the variable was even read.
- Recommended direction: print the received value and the accepted list in the message (`HOSTED_RUNNER='ubuntu-22.04-arm' is not in the helper's accepted set: macos-14, ...`); mirror that list in the `ci.md` variable table so the operator never needs the source.
- Acceptance check: `env -i HOSTED_RUNNER=ubuntu-22.04-arm GITHUB_OUTPUT=/dev/null python3 github-runner/scripts/select_runner.py` -- fails now (message contains neither the received value nor any accepted label); passes when stderr names the received value and enumerates the accepted labels.

#### U5 (Medium) -- identity mismatch reported as "not root" -- CONFIRMED

- Surface: `github-runner/scripts/prepare_runner.py:46-47`.
- Scenario: the operator types `--expected-user ci_user` for an account named `ci-user`, or runs the documented command from the admin shell before switching accounts. Output: `Preparation/inspection refused: "Run as the verified standard runtime account, not root"` (run 1), while the caller is not root. The operator concludes they must `su` to someone else, or that the helper misdetects root, and re-works the environment instead of fixing the flag.
- Recommended direction: split the two conditions and name both accounts: `Current account 'diego' is not the expected runtime account 'ci_user'` vs `Refusing to run as root`.

#### U6 (Medium) -- archive refusals name no entry or value -- CONFIRMED

- Surface: `github-runner/scripts/prepare_runner.py:62-63` (checksum), `:80-82` (links/special), `:91-94` (entry points).
- Scenario: an official asset includes an entry the helper classes as "links and special entries" (`setup.md:26` anticipates this: "If an official asset has unsupported entries, inspect it"). The operator gets only `Archive links and special entries require manual review` (run 9) and must `tar -tvf` the whole archive to find which entry. Likewise `Archive is missing runner entry points` (run 8) does not say `config.sh`/`bin/Runner.Listener`, so a user who downloaded the wrong platform's archive cannot tell that from a corrupt one; `Archive checksum mismatch` (run 2) gives neither digest, so the operator cannot tell a truncated download (re-download) from a wrong-asset digest (re-copy).
- Recommended direction: include the first offending member name and type, the missing required names, and the computed digest beside the expected one (the computed value is not secret; the doc already forbids treating it as authoritative).

#### U7 (Medium) -- `macos_service.py` messages do not name the argument -- CONFIRMED

- Surface: `github-runner/scripts/macos_service.py:11-15` (shared `absolute()`), `:28-29` (account), `:35-37` (output dir).
- Scenario: (a) the dedicated account was created in Users & Groups as `Build`; the renderer says `Choose a dedicated standard runtime account.` (run 4) -- the account is dedicated and standard; the real rule is a lowercase regex, and nothing says so, so the operator is stuck or renames a working account. (b) `--home /Users/build/` (tab-completion adds the slash) yields `Use a resolved absolute non-root path without control characters.` (run 6) without saying which of `--home`, `--runner-dir`, `--path` failed or that the trailing slash is the cause. (c) a non-existent `--output-dir` gets the symlink message (run 2).
- Recommended direction: prefix each message with the flag name and echo the value; separate "does not exist" from "has symlink components"; either accept mixed-case account names or say "lowercase letters" explicitly.

## 5. Dialogue tensions

1. Security-first silence versus operator diagnosability (U1, U2). The selector treats every deviation as "route hosted, say nothing" so that no token can leak and no untrusted event learns anything. But the operator is the person who configured the variables, and the Actions log is already the trusted surface they read. Alternative to weigh: a closed vocabulary of reason codes (never exception text), emitted only when `TRUSTED_EVENT` is true or when the cause is static configuration; untrusted events keep today's silence. The static-config class could even fail hard, as `HOSTED_RUNNER` already does, since it can never succeed.
2. Refuse-and-retain versus telling the user how to get out (U3-U7, U11). Every helper is built to stop before damage and preserve state, which is right, but the conversation ends at the refusal: messages state the violated rule, not the offending value, the argument, or the next command. Alternative: a fixed message shape `<flag>=<value>: <rule>; next: <one command>`, which keeps the guards and halves the re-work.
3. Render here, execute there (U9, U4). The macOS renderer and the remote-command renderer exist precisely because the target may lack Python or the operator may not be on it, yet the renderer bakes local facts (staging path) into the privileged plan and refuses local-idiom paths. Alternative: make the target path an explicit input, and let the plan reference a shell variable the operator sets once at the top.
4. The agent as interpreter of a gate list. SKILL.md and the references are written as gates for the agent, not as a script for the conversation with the operator: `discovery.md:3` lists twelve inputs, `SKILL.md:12,20,34` adds per-gate authorizations, and `SKILL.md:36` prescribes the report shape, but nothing says which questions to batch. An agent following the text literally can dribble a dozen single questions. Alternative: a one-screen "inputs and authorizations sheet" the agent presents once with inferred values pre-filled (remote, branch, OS/arch, current account) and only the non-inferable items (graphical login availability, admin credentials, per-gate go/no-go) left blank. This is a conversation-design gap, not a wording one; it is not a numbered finding because no transcript was produced to confirm the cost.

## 6. What held up

- `remote_command.py` success path: a single, correctly double-quoted `ssh -t -l <admin> -- <host> 'sudo -- /bin/bash -- <script>'` line, two of three flags documented, no connection made. Good.
- `prepare_runner.py` ordering: every guard runs before the exclusive `mkdir`, so a refusal never leaves debris (runs 1-9 left no directory); success prints a JSON receipt; `inspect` prints only safe identity fields and says `exists: false` plainly for an absent directory. The rerun refusal names the next action (`inspect`).
- `macos_service.py` ending: `Rendered <plist> and <plan>; no service changes made.` says exactly what happened and what did not; artifacts are 0600; rerun refusal names the alternative ("use a new staging directory"). The plan separates stages, marks the privileged lines, and states that reboot/login-free startup remain unverified.
- `ci.yml`: `Record execution machine` prints runner name, OS, arch and commit, which is the single most useful line for the operator; the failing placeholder step says in its own output what to replace; the PAT-bearing job is commented as such; `HOSTED_RUNNER` is validated before any API request.
- `credentials.md` and `setup.md` keep tokens and passwords in the operator's own terminal/UI and out of chat, logs and PRs, and say so at every point of use.
- `SKILL.md:36`: "Lead with current verdict, completed gates and smallest next action" is the right report contract for the operator, and `tests/scenarios.md` shows it producing correct verdicts on the four synthetic cases.
